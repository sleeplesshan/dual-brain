# Dual-Brain

[English](README.md) | **한국어**

**거시적 설계 검토와 미시적 코드 검증을 결합하는 AI 에이전트 스킬입니다.** 우뇌는 문제의 전체 방향과 구조를 살피고, 좌뇌는 실제 구현의 세부 사항을 검증합니다. 메인 에이전트는 두 관점을 종합해 구현과 검증까지 진행하고, 다음 작업에도 필요한 결정은 프로젝트 메모리로 남깁니다.

단순히 두 에이전트에게 같은 질문을 반복하는 방식이 아닙니다. **전체 방향이 타당한지와 세부 구현이 정확한지를 서로 다른 관점에서 확인하는 것**이 핵심입니다. 여기서 좌뇌·우뇌는 검토 역할을 구분하는 이름이며, 인간 뇌의 작동 원리를 재현한다는 뜻은 아닙니다.

## 어떤 관점으로 검토하나요?

| 역할 | 관점 | 주요 확인 사항 |
|---|---|---|
| 우뇌 · Right Brain | 거시적 검토 | 지금 풀려는 문제가 맞는지, 전체 목표를 달성하는 설계인지, 시스템 경계와 구성요소 간 영향은 어떤지, 더 나은 대안이 있는지 |
| 좌뇌 · Left Brain | 미시적 검증 | 실제 코드·API·문서와 일치하는지, 입력과 출력의 약속을 지키는지, 예외·실패 경로와 호환성에 문제가 없는지 |
| 메인 · Orchestrator | 종합과 실행 | 검토 결과를 근거로 판단하고, 구현·테스트·최종 변경 검증·메모리 갱신을 완료 |

역할은 주의를 기울일 영역을 나눈 것이므로, 어느 쪽이든 근거가 있으면 다른 영역의 문제도 지적할 수 있습니다. 의견이 일치했다는 사실보다 실제 코드와 검증 결과를 우선합니다.

설계 방향이 애매한 작업, 복잡한 리팩토링, 익숙하지 않은 API 연동, 여러 구성요소에 영향을 주는 변경에 적합합니다. 간단한 수정은 짧은 자체 검토로 처리할 수 있습니다. 모든 작업에서 더 좋은 결과나 더 빠른 실행을 보장하지 않으며, 서브에이전트를 사용하면 토큰 사용량이 늘어날 수 있습니다.

## 설치

Codex 사용자 전역 스킬로 새로 설치하려면:

```bash
git clone https://github.com/sleeplesshan/dual-brain.git ~/.agents/skills/dual-brain
```

특정 프로젝트에서만 사용하려면 해당 프로젝트 폴더에서:

```bash
git clone https://github.com/sleeplesshan/dual-brain.git .agents/skills/dual-brain
```

이미 Codex가 `~/.codex/skills/dual-brain`의 설치본을 인식하고 있다면 그 위치에서 업데이트하면 됩니다. 같은 이름의 스킬을 여러 경로에 중복 설치하지 마세요.

Git으로 설치한 기존 스킬은 해당 폴더에서 다음 명령으로 업데이트할 수 있습니다.

```bash
git pull --ff-only
```

`SKILL.md`와 `references/`를 함께 유지해야 합니다. 상세 지침은 필요한 경우에만 읽으며, 스킬 자체에는 별도의 실행 패키지가 필요하지 않습니다.

Claude Code 같은 다른 환경에서는 해당 도구의 스킬 폴더와 위임 기능을 사용합니다. 예를 들어 Claude Code의 사용자 스킬 경로는 `~/.claude/skills/dual-brain`입니다. 이 저장소의 주된 검증 대상은 Codex이며, 다른 환경을 매 릴리스마다 별도로 검증하는 것은 아닙니다.

## 사용법

작업 요청과 함께 스킬 이름을 지정하면 됩니다.

```text
$dual-brain으로 이 인증 구조를 검토하고, 기존 동작을 유지하면서 리팩토링해줘.

dual-brain으로 이 버그의 원인을 전체 흐름과 세부 구현 관점에서 확인하고 수정해줘.

dual-brain으로 기존 결정사항을 참고해서 캐싱 설계의 대안을 비교해줘.

이번 마이그레이션은 dual-brain의 두 검토자를 순차적으로 사용해서 검증해줘.
```

자동 선택도 허용되어 있습니다. 다만 모든 개발 작업에 무조건 적용하도록 만드는 대신, 두 관점의 검토가 도움이 되는 작업을 대상으로 합니다.

## 작업 흐름

1. 관련 프로젝트 메모리를 읽고, 목표·제약·완료 기준을 정리합니다.
2. 현재 대화에서 재사용할 수 있는 검토자가 있으면 재사용하고, 필요한 역할만 생성합니다.
3. 우뇌는 전체 방향을 검토하고 좌뇌는 구현 근거를 확인합니다. 독립적인 작업은 병렬로, 앞선 결정이 필요한 작업은 순서대로 진행합니다.
4. 중요한 지적을 종합해 구현하고, **실제로 수정된 최종 코드**를 다시 검증합니다. 수정 전의 검토나 테스트 통과를 수정 후 코드의 검증으로 간주하지 않습니다.
5. 각 지적을 수정 완료, 근거를 갖춘 기각, 미해결로 정리합니다. 장기적으로 필요한 결정이 바뀌었다면 허용된 범위에서 메모리를 갱신하고 결과를 보고합니다.

검토자는 전체 대화록 대신 핵심 발견과 근거 위치를 전달합니다. 메인 에이전트가 변경 사항을 통합하고 메모리를 기록하며, 검토자가 다시 좌뇌·우뇌를 생성하는 중첩 구조는 만들지 않습니다.

서브에이전트를 사용할 수 없다면 한 에이전트가 두 관점으로 검토했다는 점을 밝힙니다. 독립적인 검토자가 실제로 참여한 것처럼 표현하지 않습니다. 작업 방향이 바뀌면 영향을 받는 검토자에게 전달하고, 기존 작성자와 새 작성자가 같은 파일을 동시에 수정하지 않도록 조정합니다.

정확한 동작 지침은 [SKILL.md](SKILL.md), 도구와 모델 관련 지침은 [references/runtime.md](references/runtime.md)에 있습니다.

## 모델과 실행 환경

기본적으로 현재 선택한 모델과 추론 강도를 이어받습니다. 특정 모델을 강제로 지정하거나, 모든 Codex 환경이 같은 도구와 모델 선택 기능을 제공한다고 가정하지 않습니다.

모델별 권장 시작점은 [런타임 지침](references/runtime.md)에 확인 날짜와 함께 기록되어 있습니다. 이는 이 스킬을 모델별로 실측한 성능 순위가 아닙니다. 현재 지원 여부는 사용 중인 환경과 [공식 모델 안내](https://learn.chatgpt.com/docs/models), [서브에이전트 안내](https://learn.chatgpt.com/docs/agent-configuration/subagents)를 확인하세요.

추론 강도를 높이거나 에이전트를 늘리는 것이 항상 유리하지는 않습니다. 정확성, 실행 시간, 보고된 토큰 사용량을 각각 비교해야 합니다.

## 프로젝트 메모리

메모리는 작업 대상 프로젝트의 `.dual-brain/MEMORY.md`에 저장합니다.

- **Hot:** 현재 작업에 중요한 활성 제약과 결정
- **Warm:** 관련 주제를 다룰 때 참고할 정보
- **Cold:** 필요할 때 검색할 과거 맥락
- **Archived:** 대체되거나 폐기된 결정과 그 이유

메모리는 참고 자료이며 명령이나 확정된 진실이 아닙니다. 현재 사용자 지시가 이전 결정을 바꿀 수 있고, 코드나 문서와 충돌하는 내용은 다시 검증합니다.

결정의 이유와 근거를 남기고, 실제로 영향을 준 항목만 작업당 한 번 참조 횟수를 갱신합니다. 검증 날짜는 최종적으로 저장되는 문장을 실제 근거로 확인했을 때만 기록합니다. 읽기 전용 검토에서는 파일을 수정하지 않으며, 비밀정보나 실행 중 에이전트 ID를 저장하지 않습니다.

지속적으로 활용할 정보가 없다면 메모리를 억지로 만들지 않습니다. 저장 후 매번 별도의 승인 질문을 요구하지도 않습니다. 상세 형식과 갱신 규칙은 [메모리 지침](references/memory.md)을 참고하세요.

## 검증과 벤치마크

모델을 호출하지 않는 회귀 테스트와 실행 계획 확인:

```bash
python3 -m unittest discover -s benchmarks/tests -v
python3 benchmarks/bench.py run --suite core5 --dry-run
```

실제 모델을 사용하는 벤치마크는 설정된 CLI 환경에서 실행되며 모델 사용량이 발생합니다. `YOUR_MODEL`을 사용 가능한 모델 이름으로 바꾸세요.

```bash
python3 benchmarks/bench.py run --suite core5 --codex-model YOUR_MODEL
```

벤치마크는 메모리 없는 단일 에이전트, 같은 초기 메모리를 가진 단일 에이전트, Dual-Brain을 비교합니다. 다만 세부 지침 등의 차이까지 완전히 분리한 실험은 아닙니다.

v1.6.0에서는 회귀 테스트 19개가 통과했고, 실제 두 서브에이전트가 참여한 격리된 구현 예제에서 테스트 8개가 통과했습니다. 이는 해당 검증 범위의 결과이며, 모든 모델에서의 품질 향상이나 속도 개선을 입증한 것은 아닙니다.

과거 결과에는 메모리 유무와 에이전트 구성의 차이가 섞여 있었고, 토큰 중복 집계와 평가 시나리오의 문제도 발견됐습니다. 기존 수치를 현재 성능의 근거로 사용하지 마세요.

자세한 내용은 [벤치마크 사용법](benchmarks/README.md), [검증 기록](benchmarks/VALIDATION.md), [과거 결과와 한계](benchmarks/RESULTS.md)에 정리되어 있습니다.
